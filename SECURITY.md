# Security Policy

## Reporting a vulnerability in the specification

If you believe you have identified an attack class the SMFPS requirements do
not defeat, please email **security@divoltbtc.com** with a minimal description
and (if applicable) a provider-side implementation that illustrates the gap.
We follow a 90-day coordinated-disclosure policy.

## Reporting a vulnerability in a specific provider's SMFPS implementation

Report directly to the provider's security contact under their own
disclosure policy. Divolt Security Research does not accept third-party
provider findings except where the provider has explicitly asked us to
co-disclose.

## Reporting a specification errata

For non-security editorial issues (typos, clarifications, formatting), open a
GitHub issue tagged `errata` or send a PR against `draft-divolt-smfps.xml`.
